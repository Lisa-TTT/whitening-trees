# 构建和装载

在项目根目录执行。参考环境为 Windows 11、Python 3.12、PlatformIO、ESP32-S3 的 CH343 USB 串口和 STM32F407ZG 的 CH340 USB 串口。串口号以设备管理器为准。关闭占用对应 COM 口的程序。

## STM32F407 临时程序

```powershell
pio pkg install -e stm32_tools
py -3.12 scripts/build_stm32.py
```

输出 `build/stm32-jog-ram.bin`。仓库的 `images/stm32-jog-ram.bin` 可直接用于空载加载。先通过 `requirements.txt` 安装 PySerial，再执行：

```powershell
.\.venv\Scripts\python.exe scripts/load_stm32.py --port COM4
```

脚本通过现板的 RTS/DTR 进入 STM32 ROM 串口引导，核对芯片 ID，然后把程序加载并回读验证到 `0x20008000`，也就是 SRAM。脚本不会擦写 STM32 Flash。首次加载的位置估计是 `1500`，没有从舵机回读。新镜像路径可用 `--image`，只有知道当前指令位置时才用 `--start-position` 指定其它起点。RAM 镜像不能写入 STM32 Flash。

## ESP32-S3 应用

```powershell
pio run -e esp32_bench
```

应用输出是 `.pio/build/esp32_bench/firmware.bin`。如果板子已安装与此前 V4.2 台架相符的 Bootloader 和分区表，并且应用起始地址已确认为 `0x10000`，可以只写这一块应用。以下以 `esptool 4.9.0` 命令为例。先确认接对 ESP32 的串口，保持执行器动力断开。

```powershell
py -3.12 -m pip install esptool==4.9.0
py -3.12 -m esptool --chip esp32s3 --port COM5 write_flash 0x10000 images/esp32s3-jog-app-0x10000.bin
py -3.12 -m esptool --chip esp32s3 --port COM5 verify_flash 0x10000 images/esp32s3-jog-app-0x10000.bin
```

上述文件是应用镜像。新板需要先按实际模块型号准备 Bootloader 和分区表。更新 ESP32 后，使用 `115200` 波特率读启动日志。准备恢复整车固件时，使用原车另存的备份。\n
